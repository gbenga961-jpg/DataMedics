# Retention and Deletion

## Procedure

1. Read PRD §21 and the applicable project instructions before changing or reviewing retention or deletion logic.

2. Identify the upload or generated file and retrieve its authoritative PostgreSQL state.

3. Determine the applicable retention policy:
   - Original file after successful analysis: 30 days after successful analysis.
   - Original file after final permanent analysis failure: seven days after final permanent failure.
   - Canonical cleaned file: 30 days after creation.
   - Spreadsheet-safe cleaned export: 30 days after creation.

4. For original uploads with multiple analysis reports, evaluate the upload as a whole.

5. Do not start the failed-analysis retention period while a job is active or remains eligible for retry.

6. For uploads with at least one successful analysis, apply the successful-analysis policy. Set or refresh expiry to 30 days after the most recent successful analysis completion.

7. For uploads where all analyses permanently fail, apply the seven-day policy from the final permanent failure of the last eligible analysis attempt.

8. Before deleting an expired original file, verify that no active or retry-eligible job still requires it.

9. Before deleting an expired cleaned file, block new preview and download requests for the expired object.

10. For every deletion:
    - Mark deletion as pending in PostgreSQL.
    - Confirm that no active processing requires the file.
    - Request deletion from private object storage.
    - Record actual deletion time only after storage confirms success.
    - Record safe failure information if deletion fails.

11. Retry temporary storage deletion failures without reporting deletion as completed prematurely.

12. Track canonical and spreadsheet-safe cleaned objects separately. Confirm deletion of each object independently.

13. Retain permitted analysis reports, findings and cleaning summaries after file expiry.

14. Process explicit user deletion requests through the same safe deletion workflow, subject to active-job protection and applicable legal requirements.

15. Preserve the metadata needed to explain historical reports and cleaning outcomes where policy permits.

16. Verify the retention and deletion acceptance requirements in PRD §21.

17. If a task depends on unresolved legal exceptions, backup expiry or jurisdiction-specific obligations, stop and request an approved decision.

## Completion checks

- The correct retention period was applied.
- Active and retry-eligible jobs were protected.
- Expired files cannot be previewed or downloaded.
- Deletion is reported as complete only after storage confirmation.
- Temporary deletion failures remain recoverable.
- Permitted historical metadata is retained.
