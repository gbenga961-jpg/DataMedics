# DECISIONS.md

This file is the register of decisions and approvals. It exists so you can check an approval instead of guessing one.

## Rules

- Read this file before any task that reaches the point named in a "Needed before" column below. In that column, "accepted" and "ends" mean the user has said so. Why: a gated decision must never be assumed (PRD 27.1).
- If the task needs an item whose Status is Open, stop and ask the user. Why: you cannot pick for them.
- Status values: **Open** (no decision yet), **Approved** (the user chose; the choice is in the Decision column), **Deferred** (the user postponed it; do not build the thing it gates). Why: the agent must act on one reading of each word.
- Only the user sets a Status or a Decision. You edit this file only when the user's message names the ID and gives the value, and you then write exactly that, with the date. Otherwise propose the entry in your response. Why: you cannot approve your own work.
- When a Decision is recorded, use that value exactly. Do not paraphrase or substitute. Why: a near-match is a different choice.
- Do not change the approved stack (PRD 13.1) or the core models (PRD 15.1) unless the user has added an entry to the change log. Version 1 scope is covered by the scope door in AGENTS.md. Why: PRD 13.1 and 15.1 require an explicit change.
- Do not add a package that the PRD does not name and this file does not list as Approved. Propose it and wait. Why: each dependency is a security and maintenance commitment.
- Before OD-04 is Approved, any temporary parser limit must be a server-config constant named `TEMP_<NAME>`. Never show it in the UI, error text or docs as a supported limit, and list it under Assumptions. Why: PRD 7.1 allows temporary limits only if they are never shown as approved.
