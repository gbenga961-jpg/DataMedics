# CSV Upload Validation

## Procedure

1. Read the applicable CSV validation requirements in PRD §7 and the project instructions in `AGENTS.md`.

2. Confirm that the upload request has an authenticated user and an established ownership context.

3. Check the file extension and enforce the configured server-side file-size limit.

4. Validate UTF-8 encoding. Reject invalid UTF-8 and remove an initial UTF-8 BOM for parsing.

5. Parse the file with a maintained TypeScript-compatible CSV parser using bounded settings. Do not split records by commas or newline characters.

6. Validate the required CSV structure:
   - A non-empty file.
   - A header row.
   - At least one data row.
   - Non-blank header names.
   - Unique header names under the approved exact-comparison rule.
   - Consistent field counts across data records.
   - Well-formed CSV quoting.

7. Check logical parsed data-record counts, maximum columns, maximum field size and supported delimiter rules.

8. If a required limit or delimiter-detection rule remains unresolved, stop and request a decision. Do not invent a production value or heuristic.

9. For a rejected upload, return the applicable stable validation error code and a safe user-facing message.

10. Do not store or queue a rejected upload for analysis.

11. Store and queue only accepted uploads, following the approved upload workflow.

12. Verify the required validation acceptance tests in PRD §7.9.

## Completion checks

- Every required validation check has a recorded outcome.
- Rejected files are not queued for analysis.
- Accepted files satisfy the approved CSV structure and limits.
- User-facing errors do not expose internal paths, stack traces or sensitive details.
